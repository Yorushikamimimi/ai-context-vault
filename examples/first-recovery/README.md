# 第一次恢复上下文：虚构图片整理项目

本目录是填好内容的教学样例，所有项目进度、决定和日期都是虚构设定。它不包含应用源码、运行结果或真实个人档案，不是测试报告。

## 你会看到什么

```text
first-recovery/
├── AGENTS.md                         # 给 Codex 的小入口
├── AI_CONTEXT.md                     # 本样例的读取与写回规则
├── 20-Projects/
│   └── image-helper.md               # 唯一当前进度与下一步
└── 50-Workflow/logs/
    └── example-history.md            # 过去决定，不能代替当前状态
```

先打开 [当前项目记录](20-Projects/image-helper.md)，再对照 [历史记录](50-Workflow/logs/example-history.md)：过去考虑过多种导出格式，当前只选 PNG。旧记录保留，当前决定只维护在项目记录里。

这就是“当前进度”和“历史”分开的意义：新对话不用先读完过去的全部讨论，也不会拿旧想法当现在的计划。

## 用一个新对话理解样例

把下面的 `{{EXAMPLE_PATH}}` 换成本目录的实际位置，再向一个能够读取该目录的助手提出只读请求：

```text
请先读 {{EXAMPLE_PATH}}/AI_CONTEXT.md。
本次只读这个虚构样例，不读目录外资料，不写文件、不运行程序。
我想继续图片整理项目，请根据当前记录说明：
现在停在哪里、下一步先讨论什么、哪些事情还没有验证。
```

它应读取 `AI_CONTEXT.md` 和 `20-Projects/image-helper.md`，然后停下来。使用 Codex 的目录入口时，`AGENTS.md` 会先指向协议文件；其他助手也可以直接按提示读协议。

**这次不用读历史文件**：问题问的是当前停点，项目记录已经够用；也不用建立个人画像、填求职资料或扫描全部目录。

一份合理的回复示意：

> 当前项目记录设定为导入入口已完成、PNG 导出尚未实现，但本样例没有源码或运行证据，我不能确认实现及运行结果。下一步先讨论导出文件的命名和同名处理，目前没有开发或写入授权。第一版仅支持 PNG；“设想支持更多格式”不是当前计划。

回复的措辞可以不同，关键是当前决定、未知项与权限说对了。这是预期示意，不是已经执行过的恢复验收。

## 如果你想回看过去

另行明确请求：

```text
仍然只读，请查看本样例的 50-Workflow/logs/example-history.md，
解释这个虚构项目为什么从多种格式缩小到 PNG。
```

这时才需要那份历史记录。不能因为看见历史链接，就自动展开其他项目或个人资料。

## 如果以后决定改变方案

只有用户明确授权写入时，才更新 `20-Projects/image-helper.md` 中的当前决定与停点；重要变化可以在已有历史记录中加一条，并说明此前决定的日期。不要另建一份重复的“最新进度”。

本样例只展示文档组织和恢复方法。修改模板规则、编写代码、创建新任务、commit、push、部署或发布真实档案，都需要相应授权。

## 带回自己的项目

你可以沿用这种分工：一个规则入口、一份当前项目状态、按需读取的历史。未知事实保持未知，不为填满样例而猜测。

给自己的项目填写真实内容时，请放在独立的私有工作副本里，不直接把工作档案推到本公开仓库。更多模板与公开前检查见 [主 README](../../README.md)、[隐私清单](../../docs/PRIVACY_CHECKLIST.md)。
