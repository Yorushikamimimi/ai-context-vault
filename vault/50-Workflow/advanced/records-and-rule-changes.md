# Execution Records and Rule Changes

Use this when several agents or tools edit the vault and you need to know who did what, or when shared rules change often.

## One-line execution record

- After a substantive edit or review, add one line in the existing current document or event: `YYYY-MM-DD | tool / responsibility or task | what was done`. For multi-file work, list the scope once in the main record instead of signing every file.
- Keep execution, review, and owner confirmation separate. A self-check by the same agent is not an independent review. A relayed result says whose report it was. Record the owner's acceptance only when it actually happened, with its date and scope.
- Tool, responsibility, and model are different things; mention the model only when it matters for a judgement.
- Do not create a separate agent work log. Ordinary questions and mechanical fixes need no record.

## When a rule changes

- Decide whether the change is a business fact, a rule for one responsibility, or a rule shared across responsibilities. Shared rules belong in `../COLLABORATION.md`, or in one domain document that a shared entry points to by exact section. Keep the rule text in one place.
- Note briefly who is affected in the usual delivery note. If you are unsure, flag it for whoever coordinates the vault.
- An updated file, a delivered notice, and actual adoption are three different states. Do not create broadcasts, change ledgers, or extra threads for ordinary updates.
